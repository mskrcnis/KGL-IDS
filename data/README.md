# Dataset preparation

The article implementation consumes flow-level CSV files. It does not consume
PCAP files and does not run packet-to-flow extraction.

Create this directory layout inside the repository:

~~~text
data/
├── raw/
│   ├── edgeiiot/
│   │   └── DNN-EdgeIIoT-dataset.csv
│   └── wustl/
│       └── wustl_corrected.csv
└── processed/                 # generated by the pipeline
~~~

## Edge-IIoT

Download the dataset from the public Kaggle source:

https://www.kaggle.com/datasets/mohamedamineferrag/edgeiiotset-cyber-security-dataset-of-iot-iiot

Place the file named `DNN-EdgeIIoT-dataset.csv` at:

~~~text
data/raw/edgeiiot/DNN-EdgeIIoT-dataset.csv
~~~

## WUSTL-IIoT

The public source dataset and its citation are available from Washington
University in St. Louis:

https://www.cse.wustl.edu/~jain/iiot2/index.html

The repository includes the exact corrected WUSTL file used by the article at:

~~~text
data/raw/wustl/wustl_corrected.csv
~~~

This file is tracked with Git LFS. After cloning, run `git lfs pull` if the
file is only present as an LFS pointer. Its SHA-256 checksum is recorded in
[`data/SHA256SUMS.txt`](SHA256SUMS.txt).

The official source link is provided for provenance and for obtaining the
original WUSTL-IIoT release. The article reproduction uses the included
corrected derivative rather than silently substituting the original file.

### WUSTL `IdleTime` correction

In the original WUSTL-IIoT release, `IdleTime` was incorrectly recorded as
the end time of the previous occurrence of the same flow. In the included
corrected derivative, it represents the time difference between the current
occurrence's `StartTime` and the previous occurrence's `LastTime`. The first
occurrence of a flow, for which no previous occurrence exists, is assigned
zero.

After this correction, numeric modeling features, including `IdleTime`, are
standardized using a `StandardScaler` fitted on the training split only. The
same fitted scaler is then applied to the test split.

The corrected file must contain at least these columns:

~~~text
StartTime, LastTime, SrcAddr, DstAddr, Proto, Dur, Traffic, Target
~~~

`Traffic` is the five-class target used by the article, and `Target` is the
binary target retained for the preprocessing artifacts. The repository's
validator checks for these columns and will not silently substitute a
different WUSTL schema.

The official WUSTL page also warns that identity/timestamp fields can expose
attack identity. The article-faithful KG pipeline temporarily retains those
fields to construct relational features and removes them afterward, while the
baseline drops them before feature modeling.

## Generated data

Do not manually prepare the Parquet files. The scripts generate them under
`data/processed/<dataset>/`:

~~~bash
python scripts/00_validate_data.py --dataset wustl
python scripts/01_preprocess.py --dataset wustl
python scripts/02_smote.py --dataset wustl
python scripts/03_select_features.py --dataset wustl
python scripts/04_train_evaluate.py --dataset wustl --variant kgl_ids
~~~
